# 林业灵活用工核验领域约定

项目面向集体林权改革与林下产业协作场景，业务记录需要区分来源、发生时间与当前有效版本。涉及个人、机构或敏感地点的信息只应向职责范围内的角色开放，所有对外结果都应能够追溯到采用的数据版本。

## 角色

| 角色 | 职责边界 |
| --- | --- |
| `admin` 联盟管理员 | 登记地块/班组/村民/任务、裁决工时申诉、批准待结算工时、查看全部审计 |
| `foreman` 带班人 | 登记任务、汇总补传本班组事件、登记收尾、提交复核、为本班组发起申诉 |
| `member` 务工村民 | 查询本人脱敏范围内的信息、仅为本人发起申诉 |

所有请求携带 `X-Actor-Id`；无身份或越权操作返回 `401/403` 并写入审计。

## 登记对象

* **地块（plot）**：归属基地，登记作业允许的粗网格编码列表（村组/网格级，非经纬度）。
* **班组（crew）**：一名带班人与成员名单；同一村民可加入多个班组（跨基地灵活务工的前提），重复登记须姓名一致，防止冒名。
* **任务（task）**：绑定地块与班组，带计划开工/完工窗口。状态机：

```
draft（离线补传中）──带班人锁复核──▶ locked ──管理员批准──▶ approved
        │                              ▲
        └──未闭合会话可走申诉，支持后才能锁定
```

任务一旦 `locked`，任何事件补传一律拒绝（`task_locked`），管理员也不能例外，
以替代"管理员事后任意补数"的旧做法。

## 事件与离线语义

事件类型：`start / pause / resume / complete / handover`。

* **倒序到达**：客户端按任务维护单调 `seq`（从 1 起），服务端按
  `(seq, occurred_at, 接收回执)` 归一化，先到完工、后到开工也能重放出同一条时间线。
* **幂等补传**：`event_id` 去重，离线重试不重复入账，返回 `accepted/duplicated`。
* **时间必须带时区**：不带时区偏移的时间直接拒绝，避免跨午夜作业误算。
* **延迟标注**：发生到送达超过 72 小时标 `late_submission`，接受但可解释。
* **临时换人**：显式 `handover` 记录交接；未交接就由他人 `start`，系统在该时点
  自动收尾前任片段并打 `implicit_handover` 告警，不吞掉任何痕迹。
* **跨午夜**：片段打 `crosses_midnight` 标记；暂停间歇（`break`）不计工时。
* **超长片段**：连续作业超 12 小时提示 `long_session`。
* **未闭合会话**：缺少暂停/完工的开工挂起任务锁定；带班人可在计划完工后
  3 小时宽限内登记收尾（`foreman_closed`），超出宽限或争议须走申诉。

## 证据与位置最小化

* 照片、佐证材料只登记 **SHA-256 摘要**，不接收文件本身；
  摘要在任意事件重复出现即标 `photo_digest_reused`，对应片段分钟在结算时暂扣，
  管理员经申诉核实可豁免。
* 请求中出现 `lat/latitude/lng/longitude/gps/coords/coordinates` 等原始定位字段
  一律拒绝；只接受网格编码。网格不在地块登记范围仅告警，不丢真实劳动记录。
* 任务批准后，事件与锁定快照中的全部网格编码被删除，只保留"是否在范围内"的
  布尔结论（`location_cells_purged`）。

## 冲突检测

`GET /tasks/{id}/conflicts`（本班组）与 `GET /conflicts`（仅管理员）输出：

* `overlaps`：同一村民跨任务时间重叠，标注是否 `cross_base` 及重叠分钟；
  结算时重叠分钟从相关任务暂扣。
* `photo_reuses`：重复使用的照片摘要、首次事件与复用事件。
* `unclosed_sessions` / `sequence_gaps`：未闭合会话与缺失事件序号。

## 工时申诉

任务锁定后可就真实存在的冲突发起申诉（`overlap_dispute / photo_dispute`），
未闭合会话在补传阶段即可申诉（`unclosed_session`）：

* 重叠申诉必须能匹配到该村民的真实重叠，且申诉分钟不得超过重叠分钟；
  照片申诉的 `ref` 必须指向复用事件——凭空申诉直接拒绝。
* 仅 `admin` 可裁决，`upheld` 可批准不超过申诉分钟的工时，**决定理由必填**；
  已决申诉不可更改。
* 存在 `open` 申诉时任务禁止批准；批准补发分钟叠加进待结算工时。

## 待结算工时规则

```
payable = work_minutes − 暂扣(照片存疑 ∪ 跨任务重叠) + 申诉批准分钟
```

* 两类暂扣取并集上限，同一分钟不重复扣减；全部扣减项在结算响应中保留明细。
* 每行包含 `work_minutes / photo_held_minutes / overlap_held_minutes /
  appeal_award_minutes / payable_minutes`，并标注涉及基地。
* 结算响应携带 `data_version`，对应审计链版本，结果可追溯。

## 审计与隐私

* 所有写操作追加到哈希链（前条哈希 + 内容哈希），
  `GET /audit/verify` 重算全链，任何事后改写都会返回 `intact=false`。
* 村民姓名按职责可见：本人、本班组带班人、管理员见全名，其他角色见脱敏名
  （首字 + `*`）；每一次访问（含被拒绝的越权访问及其目的）都写入
  `/audit/access`，仅管理员可查。
